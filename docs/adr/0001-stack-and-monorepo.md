# ADR 0001: Stack and monorepo layout

- **Status:** Accepted
- **Date:** 2026-09-25
- **Related:** [ADR 0002](0002-domain-and-api-conventions.md), [API contract](../api/contract.md)

## Context

Friends is an app where small friend groups turn "we should do that sometime" into plans. It has a
shared backlog of ideas, a calendar, polls, and a "what should we do" wheel.

Constraints:
- **One developer**, working on a **Windows 11** machine with **no Mac**. Android and web are the
  real test targets; iOS only has to compile.
- The public repo `urdaraluca/friends` holds both the app and the backend. The backend is
  self-hosted on a **Raspberry Pi 4/5 (arm64)**, where networking and a reverse proxy already exist.
- Load is tiny: a few groups of friends. Operational simplicity (one container, one file-based
  database, manual updates) matters more than scale.
- Later features (push notifications, an availability heatmap, a monthly/annual recap) must not
  need a rewrite.

## Decision

### Monorepo layout

```
backend/   FastAPI service; uv "virtual" project; Python package friends_api/
           friends_api/{main,api,deps,cli,db_models}.py, core/, features/<feature>/{router,schemas,models,service}.py
           alembic/ (batch mode), tests/{unit,api}/, openapi.json (committed snapshot), Dockerfile
app/       Flutter app (android, ios, web); org io.github.urdaraluca, project "friends"
           lib/core/{config,api/generated,network,auth,router,theme,widgets,utils,prefs}
           lib/features/<feature>/{data,domain,presentation}; env/*.json; swagger_parser.yaml
deploy/    docker-compose.yml, .env.example, update.sh, README.md (Pi runbook with restore drill)
docs/      adr/, api/contract.md, api/rrule_cases.json
.github/   workflows/{backend-ci,backend-image,app-ci}.yml, actions/flutter-setup/, dependabot.yml
```

The Python package is named `friends_api`, not `app`, so it can't be confused with the Flutter `app/`
folder. Release tags carry a prefix per project (`backend-vX.Y.Z`, `app-vX.Y.Z`), because the two
can't share one version stream.

### App

- **Flutter** for Android, iOS and web.
- **material_ui** (Material now ships outside the SDK). go_router 18 needs it for page transitions
  (flutter/flutter#192761).
- **Riverpod 3** with code generation, and riverpod_lint through `plugins:`.
- **go_router 18**.
- **dio**, with **retrofit** clients and **freezed** models generated by **swagger_parser** from the
  backend's OpenAPI snapshot. The generated DTOs are the models.
- The access token lives only in memory; the refresh token is stored with `flutter_secure_storage`
  (Android auto-backup is off). table_calendar sits behind our own
  `calendar_view.dart` wrapper. The wheel is our own `CustomPainter`.

### Backend

- **FastAPI with sync `def` endpoints** on **SQLAlchemy 2.0** and **SQLite** (WAL, `BEGIN IMMEDIATE`
  for writes), with **Alembic** migrations.
- **One uvicorn worker.** SQLite has one writer anyway, and the in-process rate limiter relies on a
  single process.
- **No aiosqlite and no async ORM.** They would add complexity (greenlet, `MissingGreenlet`, async
  fixtures) and bring no real async I/O on SQLite.
- Passwords use argon2-cffi directly. JWTs use PyJWT (HS256). Recurrence uses python-dateutil.
  **tzdata** is a runtime dependency because Windows has no IANA database.
- Tooling: **uv** (the lockfile is committed), ruff, mypy (strict, with the pydantic plugin), pytest,
  time-machine.

### Delivery

- A multi-stage uv **Dockerfile** that installs wheels only (`uv sync --locked --no-build`). It runs
  as non-root uid 10001, with a `/data` volume and a HEALTHCHECK on `/api/v1/health`. The entrypoint
  runs `cli migrate`, which backs the database up first.
- GitHub Actions builds **`linux/arm64` on the native `ubuntu-24.04-arm` runner** (no QEMU) and pushes
  to **GHCR** as `ghcr.io/urdaraluca/friends-backend`. Image tags:
  - releases: `X.Y.Z`, `X.Y` and `latest`;
  - `main` for the tip of main;
  - `sha-*` for exact commits.
- **Same-origin web:**
  - CI builds the Flutter web app on x64 and passes it into the image through a named build context
    (`build-contexts: web=…`, which overrides a `FROM scratch AS web` stage);
  - FastAPI serves it at `/` with an SPA fallback, next to `/api/v1`;
  - production needs no CORS, and invite links (`/join/{code}`) and `/.well-known/assetlinks.json`
    are served from the same host.
- The Pi runs `deploy/docker-compose.yml`:
  - the port is bound to `127.0.0.1` by default;
  - the container is `read_only` with a tmpfs, `no-new-privileges` and `mem_limit: 512m`;
  - the database lives on a named volume;
  - backups use a bind mount on USB or NAS storage.
- **Updates are manual** with `deploy/update.sh` (pull, `up -d`, prune), with releases pinned by tag.
  **No Watchtower:**
  - containrrr/watchtower was archived on 2025-12-17 and breaks on current Docker API versions;
  - unattended migrations on an SD-card database are the bigger risk anyway.
- A host cron job runs backups with `cli backup --keep 14` (SQLite online-backup API, then an integrity
  check, then gzip).

## Consequences

**Good**
- One repo, one PR for a change that touches both sides. The committed `openapi.json` and the
  generated client make API changes reviewable, and CI fails when either is stale.
- One container and one SQLite file on the Pi. Backups are a file copy, restores are a documented
  drill, and there is no database server to run.
- Native arm64 builds are fast and free on a public repo. The build uses wheels only, so it never
  compiles C extensions.
- Same-origin hosting removes CORS in production, makes invite links and App Links work from one host,
  and keeps an HttpOnly-cookie web mode possible later.

**Costs and risks**
- **SQLite has a single writer and there is a single worker.** That is fine for friend-group load. If
  it ever isn't, the design (UUIDs, UTC instants, plain SQL, a service layer) keeps a Postgres move
  cheap.
- **material_ui is young** (about six weeks old). The fallback is go_router `^17.5` with the SDK's
  `MaterialApp`. Every new UI package is checked for public APIs that expose SDK Material types.
- **iOS is compile-only** until there is a Mac and an Apple Developer account. So Universal Links and
  TestFlight wait.
- **On web, the refresh token is only obfuscated** by flutter_secure_storage. That is accepted for the
  MVP given same-origin HTTPS, 15-minute access tokens, and rotation with reuse detection.
- Path-filtered workflows **must not be required status checks**, or a PR that doesn't trigger them
  blocks forever.
- **The Pi has no real-time clock.** The runbook enables `systemd-time-wait-sync` and orders Docker
  after `time-sync.target`, so token times and UUIDv7 ordering are right after a reboot.
- The owner does these once: make the GHCR package public (or give the Pi a classic PAT with only
  `read:packages`), create `/srv/friends/.env` with `JWT_SECRET` and `PUBLIC_APP_URL`, and point
  backups at USB or NAS storage.
